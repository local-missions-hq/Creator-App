# ADR-061: Use GitHub Free and a reviewed local Terraform operator path until private workflow state networking is justified

- **Status:** Accepted 2026-09-01
- **Scope:** Local Missions development source ownership and Terraform operations

## Decision

Create `local-missions-hq` on GitHub Free under the founder's personal account, enter no payment information, keep the repository public, and transfer it only through a coordinated immutable-subject migration gate. GitHub-hosted verification and no-apply OIDC/ARM proof may continue, but provider-backed Terraform state operations remain on the reviewed local operator path while the Storage account stays default-deny.

The repository was transferred publicly after an exact three-update Terraform apply. GitHub's first organization-owned proof then established that the previewed subject string was wrong: custom claim keys emit `repository_owner_id:{id}:repository_id:{id}:environment:{name}`. The proof failed before ARM access. A replacement saved plan contains exactly three subject-only corrections and no other changes; it requires separate digest-bound approval.

## Security boundaries

- Do not add a payment method, paid GitHub plan, or paid runner under this decision.
- Do not allowlist standard GitHub runner ranges or a dynamically discovered runner IP.
- Do not enable Storage all-networks mode or trusted-service bypass.
- Do not attach a self-hosted runner to the public repository or the founder's daily-use Mac.
- Keep the temporary operator Blob role until a separately approved recovery path and later workflow-state proof exist.
- Do not treat GitHub OIDC/ARM proof as remote-state data-plane proof.

## Deferred option

ADR-060's GitHub Team larger-runner/Azure VNet design moves to M14. It requires a fresh need, price review, GitHub spending approval and budget, and a separately reviewed Azure network saved plan.

## Consequences

This path has no GitHub subscription charge and preserves the Azure firewall. Terraform deployment remains a reviewed local operator activity rather than unattended CI. Until the correction plan is approved and proved, GitHub-to-Azure access is fail-closed because the three live federated credentials do not match the emitted organization-owned subjects.
