# ADR-060: Use an organization-scoped GitHub larger runner in an Azure VNet for workflow state access; do not weaken the Storage firewall or attach a self-hosted runner to the public repository

- **Status:** Deferred — the founder selected GitHub Free on 2026-09-01; reconsider at M14 only with fresh billing and Azure approvals
- **Decision date:** 2026-09-01
- **Scope:** Local Missions development workflow networking only

## Context

The three protected plan/apply/destroy identities passed live immutable-subject GitHub OIDC and exact ARM/data-permission proof in run `33513053687`. Their real Blob read failed as designed because the retained state account remains default-deny. The current repository is public and owned by the personal `stratiosai` account.

Standard GitHub-hosted runners do not provide a stable narrow network identity. GitHub publishes many runner ranges, updates them weekly, and recommends larger static-IP or self-hosted runners instead of allowlisting those ranges. Azure Storage also documents that public IP rules cannot restrict same-region Azure service traffic, so discovering one standard runner IP is not a reliable design. GitHub separately says self-hosted runners should almost never serve public repositories because forked workflow code can compromise the host.

## Deferred paid decision

1. Create a Local Missions-only GitHub organization using the currently unreserved candidate `local-missions-hq`, purchase one GitHub Team seat, and transfer `Creator-App` while keeping it public. The name check is point-in-time evidence, not a reservation.
2. Preview the new immutable organization-owner and repository IDs. Replace the three federated credential subjects only through a separately generated/reviewed retained-control-plane saved plan.
3. Add one retained East US 2 VNet, a dedicated runner subnet sized for maximum concurrency one, an NSG with no inbound internet access, the `Microsoft.Storage` service endpoint, and one exact subnet rule on the retained state account. Keep Storage `defaultAction=Deny`, Shared Key disabled, anonymous access disabled, and trusted-service bypass disabled.
4. Register `GitHub.Network` and create its network-settings resource only through the same separately approved retained delta. Review the service principal and documented subnet-level permissions before apply.
5. Create one organization runner group accessible only to `Creator-App`, attach the Azure network configuration, and use the two-core Linux larger runner at maximum concurrency one. Keep every plan/apply/destroy environment review and immutable-subject gate.
6. Prove each identity can use only its distinct state key, then reconcile the subnet rule, default deny, exact RBAC, network inventory, and cost. Remove the temporary operator Blob role only after a reviewed recovery method remains available.

The free `local-missions-hq` organization now exists, but this deferred proposal does not authorize a paid plan, provider registration, Azure network resources, firewall change, paid runner, workflow state access, RBAC removal, or workload plan. ADR-061 governs the current no-charge path.

## Cost boundary

- GitHub publicly lists Team at `$4/user/month`.
- GitHub lists the Linux two-core larger runner at `$0.006/minute`, or `$0.12` for 20 minutes and `$0.36` for 60 minutes. GitHub reports no idle runner charge.
- Azure lists the VNet foundation as free. The exact provider-backed plan must still identify any network-settings, public-IP, data-transfer, logging, or related meter before approval.
- These are dated public estimates, not quotes or approval. The existing `$100` Azure budget does not authorize GitHub billing.

## Rejected alternatives

- Do not allowlist GitHub's global standard-runner ranges.
- Do not depend on a dynamically discovered standard-runner IP.
- Do not attach a self-hosted runner to the current public repository or the founder's daily-use Mac.
- Do not change the state account to all networks.
- Do not enable a broad trusted-services bypass.

## Consequences

- The repository URL and immutable OIDC subjects change after transfer, so federation replacement must precede any post-transfer workflow run.
- GitHub Team adds a recurring non-Azure cost; larger-runner jobs add per-minute cost but no idle runner charge.
- The VNet/subnet/network-settings objects become retained control-plane resources and remain outside daily workload teardown.
- This introduces minimal private-network infrastructure earlier than M14 only for the Terraform state/automation boundary. Application data-plane private endpoints and full staging network hardening remain deferred.
- If the founder rejects the recurring GitHub cost or repository transfer, M5 workflow remote-state automation remains open; local operator Terraform must not be misreported as CI proof.

## Approval gates

Approval must be separate for: organization name/transfer, GitHub Team billing, immutable-subject migration plan, retained-network saved plan, exact retained apply, three-key state proof, temporary-operator removal, and later workload planning.
